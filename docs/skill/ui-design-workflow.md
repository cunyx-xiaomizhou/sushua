# UI 版式设计工作流

多阶段 AI 引导式 UI 设计流程，从策划案分析到逐区块实现。
当用户提供策划案/需求文档时，按照以下 5 个阶段逐步输出设计方案，每阶段需用户确认后再进入下一阶段。

---

## Phase 1: 需求分析与界面规划

**输入**: 策划案/需求文档
**输出**: 界面清单 + 版式选择

### 步骤:
1. **提取核心功能模块**: 从策划案中识别所有功能点，按用户操作流程分组
2. **确定界面数量**: 判断需要几个独立 UI 界面（每个界面对应一个 Screen）
3. **选择版式结构**: 为每个界面选择合适的版式

### 版式结构类型:

| 版式 | 适用场景 | 典型锚点布局 |
|------|----------|------------|
| **左右结构** | 列表+详情（背包、合成、商店） | 左Panel: anchor(0,0,0,1) offsets(0,0,W,0); 右Panel: anchor(0,0,1,1) offsets(W,0,0,0) |
| **左中右结构** | 三栏信息（装配、对比、配置） | 左: anchor(0,0,0,1) offsets(0,0,W1,0); 中: anchor(0,0,1,1) offsets(W1,0,W2,0); 右: anchor(1,0,1,1) offsets(-W2,0,0,0) |
| **上下结构** | 信息+操作（结算、确认弹窗） | 上: anchor(0,0,1,0) offsets(0,0,0,H); 下: anchor(0,1,1,1) offsets(0,-H,0,0) |
| **上中下结构** | 标题+内容+操作栏 | 上: anchor(0,0,1,0) offsets(0,0,0,H1); 中: anchor(0,0,1,1) offsets(0,H1,0,H2); 下: anchor(0,1,1,1) offsets(0,-H2,0,0) |
| **居中弹窗** | 确认框、提示、奖励展示 | anchor(0.5,0.5,0.5,0.5) alignment(0.5,0.5) offsets(0,0,W,H) |
| **全屏覆盖** | 主界面、加载、过场 | anchor(0,0,1,1) offsets(0,0,0,0) |

### 输出格式:
```
界面清单:
1. [界面名] - [版式类型] - [功能描述]
2. ...

版式理由: [为什么选这个版式]
```

---

## Phase 2: 骨架搭建

**输入**: Phase 1 确认的版式方案
**输出**: 在编辑器中创建骨架结构（仅容器，不含内容控件）

### 标准骨架层级:
```
CanvasPanel (Root)
├── 背景 (Panel, stretch全屏)
│   └── 底图 (Image, stretch, 背景图/纯色)
└── 前景 (Panel, stretch, offsets留边距32px)
    ├── 页面顶部信息栏 (Panel, anchor上部, 高度120px)
    │   ├── 左侧内容 (HorizontalBox)
    │   │   ├── 页面图标 (Panel, 160px宽, 可选)
    │   │   └── 标题 (Panel)
    │   │       ├── 主标题 (Text, 44px)
    │   │       └── 副标题 (Text, 24px, opacity 0.32)
    │   └── 关闭按钮 (Panel, 右上角)
    └── 主内容 (Panel, stretch, top留出顶栏高度)
        ├── [区块A] (Panel, 按版式定位)
        ├── [区块B] (Panel, 按版式定位)
        └── [区块C] (Panel, 按版式定位，可选)
```

### 执行规则:
- 使用 ```ui-command 创建骨架
- 每个区块用 Panel 占位，label 标注区块名称
- 此阶段只建容器，不放具体内容控件
- 顶栏固定模式: 标题区（主标题44px + 副标题24px opacity 0.32）

---

## Phase 3: 区块功能分配

**输入**: 骨架结构 + 策划案功能点
**输出**: 每个区块的功能职责清单

### 输出格式:
```
区块分配:
- [区块A名称]:
  功能: [具体功能描述]
  包含元素: [列表项/按钮/图标/文本/...]
  交互: [点击/滑动/拖拽/...]

- [区块B名称]:
  功能: ...
  包含元素: ...
  交互: ...
```

---

## Phase 4: 区块细化设计

**输入**: Phase 3 的区块分配
**输出**: 每个区块的详细控件树设计（文档形式）

### 设计规范（参考 component-design-spec.md）:
- 按钮: Panel(容器) > Button(底层) + Text(标题)
- 列表项: Panel(卡片) > Image(背景) + Image(图标) + Text(名称) + ...
- 标题组: Panel > 装饰(Image, 2-4px宽色条) + 主标题(Text) + 副标题(Text, opacity 0.64)
- 筛选栏: Panel(HBox或Panel) > 多个筛选按钮(Panel > Button + Text)

### 输出格式（每个区块）:
```
[区块名] 控件树:
Panel "[区块名]"
├── [子控件1] (类型, 尺寸, 定位方式)
│   └── ...
├── [子控件2]
└── ...

定位参数:
- [控件]: anchor(...) offsets(...) alignment(...)
```

---

## Phase 5: 逐区块实现

**输入**: Phase 4 确认的设计方案
**输出**: 逐区块的 ui-command 实现

### 执行规则:
1. 每次只实现一个区块
2. 实现完成后等待用户确认再继续下一个
3. 使用 batch action 批量创建同层级控件
4. 遵循组件设计规范中的命名和样式约定

### 实现顺序:
1. 先实现静态展示区块（标题、装饰、图标）
2. 再实现交互区块（按钮、列表、输入）
3. 最后实现动态区块（动画、状态切换）

---

## 流程控制指令

用户可在任何阶段使用以下指令:
- `继续` / `下一步`: 确认当前阶段，进入下一阶段
- `修改 [内容]`: 修改当前阶段的输出
- `跳过`: 跳过当前阶段（仅文档阶段可跳过）
- `重做`: 重新执行当前阶段
